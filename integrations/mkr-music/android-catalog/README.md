# Android catalog engineering library

This isolated build compiles the same pinned MKR catalog and conservative
InnerTubeX adapter for Android. It uses the multiplatform Android dependency
variant and excludes the Windows JDK HTTP/pipe sidecar and console probe.
It does not change either AnF application ID, signer, library or release build.

Use the existing Android SDK 37.0, JDK 21 and Gradle 9.4.1. Run `testDebugUnitTest`
to compile and exercise the shared catalog policy tests without a provider call.
Source preparation remains pinned and checked by `../prepare-catalog.mjs`.
The existing JVM dependency lock/source review is not an Android runtime audit;
Android dependencies, native ABIs and corresponding sources require their own
inventory before packaging.

The initial Android compile and six shared policy suites passed: 19 tests, no
failures or skipped tests. These are host JVM unit tests against the Android
library build, not Android device playback tests. `auditAndroidCatalogRuntime`
checks the actual Android InnerTubeX AAR, rejects desktop/native Windows/macOS
artifacts and requires aligned Ktor versions. `runtime-evidence.json` records
62 runtime artifacts and the QuickJS Android native entries for arm64-v8a,
armeabi-v7a, x86 and x86_64. Listing an ABI is not device verification.

The generated-source task uses the supported AGP variant API with a task-owned
output directory, avoiding the AGP 9.2.1 library source-set cast defect. It
copies only shared catalog Kotlin sources; Windows sidecar and console sources
never enter this library. Build instructions:

```
gradle --offline --no-daemon --no-configuration-cache auditAndroidCatalogRuntime testDebugUnitTest
```

Use normal strict dependency verification after the initial pinned dependency
bootstrap; do not regenerate checksums merely to accept changed artifacts.

The native input layer now includes an opaque lease and Media3 `DataSource`:
signed CDN URLs and headers remain native, reads use exact bounded ranges,
and expiry/revocation or malformed/denied responses stop the lease. A dedicated
OkHttp client has no cookies, authentication callbacks, redirects, automatic
retries or disk cache. Ten generated-response input tests bring the host suite
to 29 passing tests, including cross-input denial/size latches and reopen safety.
These tests make no provider requests. First-chunk requests now honor short
Media3 ranges without overfetching, and overflow/EOF boundaries have host tests.

The native controller and ExoPlayer engine now compile. The controller requires
an acknowledged handoff before resolving/playing, cancels owned preparation and
search jobs, rejects late play after pause, retains pause/seek positions and
owns queue/lease cleanup. Shutdown completes native release even from a cancelled
owner coroutine. ExoPlayer uses only the opaque-lease progressive source with
automatic load retries disabled. All player access is on the Android main thread.

That controller milestone passed 41 host tests: 19 catalog/policy, 12 input/bounds/privacy
and 10 controller tests with fake audio. Compiling ExoPlayer is not native
decoder or framework lifecycle acceptance.

Three separate instrumentation tests cover real Android `DataSpec` behavior,
muted Media3 AAC decode/progress/seek/pause/resume and a single-attempt denied
source. Their only APK identity is `com.anf.mkr.catalog.test`; their 43 KB audio
asset is a generated tone with a checked hash. They inject generated byte ranges
in-process and never contact a music provider or open an external player.
The `MKR Android native QA` workflow runs them on an isolated Android 15 emulator
and retains reports only. Emulator results remain separate from host unit tests,
production-app integration, physical-device tests and update-signer verification.

This is not an available in-app player. Foreground service/notification and production application integration,
the real cross-engine handoff/bridge and emulator/device/provider
acceptance remain required. No production capability is enabled by this build.
Prepared upstream sources retain their original licenses; this build adapter
does not change AnF's repository-wide license or approve a combined distribution.

## Android system media controls

`AndroidMediaSession` owns a controller and a platform media session. It remains
inactive until explicit activation. Play, pause, stop, selected track, previous,
next and seek callbacks use the same controller and acknowledged audio handoff;
URI/search/custom-action callbacks cannot bypass the selected queue. Its token
stays native. Metadata includes track identity, title, artist and duration, never
the stream URL or headers. Command/native failures publish fixed safe messages
and remain latched until an explicit successful command or refresh.

Media3 player events update the session on its main dispatcher. There is no
periodic status timer: Android extrapolates playing position from the published
speed and monotonic update time. Buffering, decoder errors and focus/play state
changes arrive through the player listener. Closing cancels owned commands,
closes the supplied controller and releases the session, including from a
cancelled owner coroutine. Do not share the supplied controller with another
session owner.

[Run42082623789](https://github.com/mwalikokelvo/AnF/actions/runs/42082623789)
at `d025b95` passed43 host tests and7 Android15 instrumentation tests with strict
dependency verification and the unchanged62-artifact runtime graph. This includes
actual platform MediaController/MediaSession transport and one joint route through
the controller to muted Media3 decoding of the hash-checked generated AAC. Other
session edge cases use fake catalog/audio; no test contacted a music provider.
An internal lease factory enables that generated transport in tests; its default
is the original native lease construction, with no renderer or environment input.
The denial fixture still requires one request, a decoder error and a revoked
lease whether denial latches before or after the play command.

These checks do not verify foreground service survival, notifications, actual
AnF app wiring, physical devices, provider access or signed installed upgrades.
No manifest permissions, production app IDs, signers, dependency versions or
availability flags changed. This library is not linked into either release app.

## Foreground service and system notification

`MkrPlaybackService` is an isolated host for the same controller and native
media session. Its internal `start` API transfers a prepared controller from a
foreground user action; the service never constructs a provider or accepts a
stream URL. Only one prepared owner can be pending/running. An unaccepted,
cancelled or rejected handoff closes that controller; after acceptance the
service owns it independently of the Activity. Startup is bounded and failed
initialization releases the controller/session. Process restoration is disabled.

The host promotes itself promptly using the mediaPlayback foreground-service
type and a low-importance, silent channel. A framework MediaStyle notification
contains previous, play/pause, next and explicit Stop controls. Intent actions
are immutable, explicit and scoped to the current random owner; stale actions
cannot stop a successor. Stop removes the notification and closes the session,
native leases, decoder and catalog. Session callbacks update the notification
without a polling timer. The only content navigation intent is this app's own
launcher, when present.

The service and its two ordinary foreground-service permissions are declared
**only in the disposable instrumentation manifest**. Neither production app
manifest registers it, and there is no renderer capability/readiness change.
AnF app bootstrap/bridge, physical-device acceptance, distribution/source review,
provider access and signed upgrade compatibility remain separate release gates.
Do not invoke this host automatically from a background receiver or boot event.

The new instrumentation scenario uses a fake catalog and hash-checked generated
AAC through real muted Media3, framework media controls and the actual service.
It checks acknowledged audio handoff, MediaStyle/foreground notification identity,
Activity-independent resume/progress, stale-owner rejection and explicit Stop
cleanup. [Run42088458462](https://github.com/mwalikokelvo/AnF/actions/runs/42088458462)
at `da6a061` passed strict compilation,43 host tests and all8 Android15 API35
instrumentation cases, with the unchanged62-artifact runtime graph. The service
scenario passed using real OS notification actions after Activity finish.
This is isolated component evidence, not a production APK, physical-device test,
provider access, signer compatibility or installed upgrade verification.

Platform references: [foreground service launch rules](https://developer.android.com/develop/background-work/services/fgs/launch)
and [mediaPlayback service requirements](https://developer.android.com/develop/background-work/services/fgs/service-types#media).

## Native browsing connection

`AndroidMkrConnection` binds a native Activity to an already approved service
session. The same-process Binder exposes catalog search and typed playback
status, plus the framework token for standard playback controls. It exposes no
source URL, request headers, decoder or raw controller. Closing a connection
detaches that UI without stopping accepted background playback. Search uses the
existing catalog validation/selected-queue policy and does not resolve a stream.

Every connection rechecks the current session token, including when Android
reuses a cached Binder. A stopped/stale session cannot answer browsing requests.
The service retains its ownership reservation through cleanup and actual service
destruction; bound clients must detach before a successor can be started.
Cancellation unregisters the binding both while waiting for connection and when
a successfully bound result is discarded during return to a cancelled caller's
dispatcher. Unbind is serialized on Main and repeated closes are harmless.

This is a native library connection, not an installed JavaScript bridge or an
AnF release-app bootstrap. Production manifest registration, reviewed dependency
packaging/licensing and actual app integration remain separate gates. [Run42096801862](https://github.com/mwalikokelvo/AnF/actions/runs/42096801862)
at `5b77657` passed strict compilation,43 host and9 Android15 instrumentation
tests, with the unchanged62-artifact runtime graph. This includes the real
cached-Binder token check, native browsing after service start, UI detachment,
stopped bound-owner/successor lifecycle and deterministic cancellation while
the bound result waits in the caller dispatcher. Generated AAC/fake catalog
only; no provider requests or production application availability are inferred.

References: [Android bound service lifecycle](https://developer.android.com/develop/background-work/services/bound-services)
and [cancellable result delivery](https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-core/kotlinx.coroutines/-cancellable-continuation/resume.html).

## Trusted WebView transport

`AndroidMkrWebPort.attach` transfers a framework MessagePort to the trusted
main document at exactly `https://anf.local` or `https://coucou.local` after
loading. The host must revoke it on every main navigation and Activity destroy.
It does not install a JavascriptInterface, launch a browser or accept a stream
URL. Closing cancels page requests and detaches its native connection; the
foreground service retains its accepted playback ownership. The transferred
JavaScript endpoint is owned by JavaScript and is never closed from Java.

Messages are `{id,command,payload}` and responses are `{id,value,error}`.
Commands match the existing renderer contract: capabilities, open, hide, status,
search, play, pause, previous, next and seek. Only a live approved session can
report embedded capabilities. The transport bounds input size/nesting, concurrent
requests and IDs; it rejects extra payload fields, arbitrary URLs, unsupported
commands and coerced numeric strings. Errors are fixed messages; only track
identity/title/artist and playback state are serialized. No signed URL/headers
or raw native errors enter the page.

Native app and OS controls share the session's revision/error publishing and
controller acknowledgement/selected-queue policy. The app host still supplies
its real pause-other-audio acknowledgement callback; this transport does not
automatically approve it. Actual AnF Activity bootstrap/renderer port adapter and
reviewed source/dependency packaging remain release gates. This engineering
library is not registered in the installed applications.

A new instrumentation test uses a real Android WebView, channel, Binder,
foreground service/session and muted Media3 with a fake catalog and generated
AAC. It also tests invalid numeric types/unknown tracks/URL payloads/unsupported
launch requests, native audio acknowledgement, strict foreign/wildcard origin
rejection and deeply nested input revocation. [Run42110704864](https://github.com/mwalikokelvo/AnF/actions/runs/42110704864)
at `71de9bc` passed strict compilation,43 host tests and all10 Android15
instrumentation tests, with the unchanged62-artifact runtime graph. It exercised
the real JavaScript-to-Media3 path and all existing native tests. The fixture uses
matching HTTPS base/history URLs; no about:blank/wildcard origin exception was
introduced. The service now awaits final unbound teardown before starting a
successor, retaining rejection while a stopped owner remains bound.

Initial run42109204759 failed on the asynchronous service teardown race and the
fixture's current-URL guard. Those failures are retained separately. Final
validation did not remove guards, skip tests or increase test deadlines.
This proves isolated WebView/native transport with generated media, not an
installed AnF renderer integration, provider playback, visual screenshot review,
physical-device behavior or signed upgrade compatibility.

## Android Music Hub client

The shared `mkr-web-port.ts` is now the page-side counterpart to this native
channel. Android Music Hub mounts the existing MKR browser/dock and keeps its
source button hidden until a real native channel confirms capabilities. It has
no browser/player fallback and does not change desktop native transport.
Local music works as before when no native MKR port has ever been announced.

The client requires a native (null Window-source) announcement on an exact AnF
page origin; a null event origin alone grants nothing. It bounds pending requests,
IDs, payload/response size and deadlines, validates response envelopes, masks raw

announcement cannot silently permit another engine, including before capability
confirmation. MKR's own before-play path pauses other engines without waiting on
itself. The real native/renderer handoff coordinator still belongs to the pending
Activity bootstrap; these changes never automatically approve native handoff.

## Current-page audio acknowledgement

`AndroidAudioHandoff` now implements the native/renderer acknowledgement used by
the controller's pause-other-audio callback. A host creates one coordinator for
the controller and passes that same instance when attaching its trusted page
port. Each request has a fresh one-use UUID, a current-page identity and a
monotonic4-second deadline checked at acknowledgement and verdict return.
Replacement, stale/duplicate/wrong tokens, cancellation, timeout and detached
pages deny playback. Closing an old page cannot detach its successor.

The native port sends `pause-others`; the shared TS client awaits its real
pause-others callback and replies privately with `audio-ack`. Android main uses
its existing pauseForMkr routine, including awaited native/Spotube/media pauses,
without pausing MKR itself. A missing/rejected callback or3.5-second renderer
deadline sends a negative acknowledgement. Replaced/closed/superseded callbacks
cannot send a late positive response. No callback automatically grants playback.

at `86db689` passed strict compilation, frontend policy checks/asset build,
43 host and all12 Android15 instrumentation tests with the unchanged62-artifact
runtime graph. The actual WebView/TS/native-controller test holds simulated
other-engine completion, requires zero stream/decoder requests before positive
acknowledgement, then decodes generated AAC and performs a second fresh handoff.
Two additional native cases cover token/page ownership/cancellation and the real
4-second timeout. The initial run failed JUnit discovery because a coroutine test

This proves the channel/coordinator with a fixture completion callback, not real

inspects native ELF headers without building an instrumentation APK or starting

## Bound browsing preparation (engineering only)

`MkrPlaybackService.prepare(context, freshController)` consumes a fresh native
controller and returns a browsing-only lease with search, status and close.
The service owns an accepted controller; failed/unaccepted preparation releases
it. Never share that controller with another owner or reuse it after transfer.
The bootstrap binding stays alive until a normal token-validated native binding
is retained. Closing the final cold lease releases the unstarted service;
closing a started foreground connection retains the existing playback behavior.

Preparation creates no foreground notification. With deferred native playback,
it also creates no decoder. Unpromoted sessions reject system/Binder play and
queue controls before handoff, source resolution or decoding. The prepared lease
intentionally does not implement the playable page contract: explicit selected
play/promotion and actual AnF Activity integration are still pending. Do not use
this browsing API as an available/playable-source flag.
