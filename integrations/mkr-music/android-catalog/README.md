# Android catalog engineering library

This isolated build compiles the same pinned MKR catalog and conservative
InnerTubeX adapter for Android. It uses the multiplatform Android dependency
variant and excludes the Windows JDK HTTP/pipe sidecar and console probe.
It does not change either AnF application ID, signer, library or release build.

Use the existing Android SDK 37.0, JDK 21 and Gradle 9.4.1. Run `testDebugUnitTest`
to compile and exercise the shared catalog policy tests without a provider call.
Source preparation remains pinned and checked by `../prepare-catalog.mjs`.
The existing JVM dependency lock/source review is not an Android runtime audit;
Android dependencies, native ABIs and corresponding sources require their own
inventory before packaging.

The initial Android compile and six shared policy suites passed: 19 tests, no
failures or skipped tests. These are host JVM unit tests against the Android
library build, not Android device playback tests. `auditAndroidCatalogRuntime`
checks the actual Android InnerTubeX AAR, rejects desktop/native Windows/macOS
artifacts and requires aligned Ktor versions. `runtime-evidence.json` records
62 runtime artifacts and the QuickJS Android native entries for arm64-v8a,
armeabi-v7a, x86 and x86_64. Listing an ABI is not device verification.

The generated-source task uses the supported AGP variant API with a task-owned
output directory, avoiding the AGP 9.2.1 library source-set cast defect. It
copies only shared catalog Kotlin sources; Windows sidecar and console sources
never enter this library. Build instructions:

```
gradle --offline --no-daemon --no-configuration-cache auditAndroidCatalogRuntime testDebugUnitTest
```

Use normal strict dependency verification after the initial pinned dependency
bootstrap; do not regenerate checksums merely to accept changed artifacts.

The native input layer now includes an opaque lease and Media3 `DataSource`:
signed CDN URLs and headers remain native, reads use exact bounded ranges,
and expiry/revocation or malformed/denied responses stop the lease. A dedicated
OkHttp client has no cookies, authentication callbacks, redirects, automatic
retries or disk cache. Ten generated-response input tests bring the host suite
to 29 passing tests, including cross-input denial/size latches and reopen safety.
These tests make no provider requests. First-chunk requests now honor short
Media3 ranges without overfetching, and overflow/EOF boundaries have host tests.

The native controller and ExoPlayer engine now compile. The controller requires
an acknowledged handoff before resolving/playing, cancels owned preparation and
search jobs, rejects late play after pause, retains pause/seek positions and
owns queue/lease cleanup. Shutdown completes native release even from a cancelled
owner coroutine. ExoPlayer uses only the opaque-lease progressive source with
automatic load retries disabled. All player access is on the Android main thread.

That controller milestone passed 41 host tests: 19 catalog/policy, 12 input/bounds/privacy
and 10 controller tests with fake audio. Compiling ExoPlayer is not native
decoder or framework lifecycle acceptance.

Three separate instrumentation tests cover real Android `DataSpec` behavior,
muted Media3 AAC decode/progress/seek/pause/resume and a single-attempt denied
source. Their only APK identity is `com.anf.mkr.catalog.test`; their 43 KB audio
asset is a generated tone with a checked hash. They inject generated byte ranges
in-process and never contact a music provider or open an external player.
The `MKR Android native QA` workflow runs them on an isolated Android 15 emulator
and retains reports only. Emulator results remain separate from host unit tests,
production-app integration, physical-device tests and update-signer verification.

This is not an available in-app player. Foreground service/notification and production application integration,
the real cross-engine handoff/bridge and emulator/device/provider
acceptance remain required. No production capability is enabled by this build.
Prepared upstream sources retain their original licenses; this build adapter
does not change AnF's repository-wide license or approve a combined distribution.

## Android system media controls

`AndroidMediaSession` owns a controller and a platform media session. It remains
inactive until explicit activation. Play, pause, stop, selected track, previous,
next and seek callbacks use the same controller and acknowledged audio handoff;
URI/search/custom-action callbacks cannot bypass the selected queue. Its token
stays native. Metadata includes track identity, title, artist and duration, never
the stream URL or headers. Command/native failures publish fixed safe messages
and remain latched until an explicit successful command or refresh.

Media3 player events update the session on its main dispatcher. There is no
periodic status timer: Android extrapolates playing position from the published
speed and monotonic update time. Buffering, decoder errors and focus/play state
changes arrive through the player listener. Closing cancels owned commands,
closes the supplied controller and releases the session, including from a
cancelled owner coroutine. Do not share the supplied controller with another
session owner.

[Run42082623789](https://github.com/mwalikokelvo/AnF/actions/runs/42082623789)
at `d025b95` passed43 host tests and7 Android15 instrumentation tests with strict
dependency verification and the unchanged62-artifact runtime graph. This includes
actual platform MediaController/MediaSession transport and one joint route through
the controller to muted Media3 decoding of the hash-checked generated AAC. Other
session edge cases use fake catalog/audio; no test contacted a music provider.
An internal lease factory enables that generated transport in tests; its default
is the original native lease construction, with no renderer or environment input.
The denial fixture still requires one request, a decoder error and a revoked
lease whether denial latches before or after the play command.

These checks do not verify foreground service survival, notifications, actual
AnF app wiring, physical devices, provider access or signed installed upgrades.
No manifest permissions, production app IDs, signers, dependency versions or
availability flags changed. This library is not linked into either release app.
