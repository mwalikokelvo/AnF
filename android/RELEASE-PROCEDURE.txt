AnF release procedure

User preference: produce matching Windows and Android packages for future updates.
Use docs/RELEASE-BUILDS.md and the Windows/Android Actions workflows.
scripts/build-android.mjs builds Android locally; Windows uses npm run pack.
Both read the version in windows/src-tauri/tauri.conf.json. Keep Cargo and frontend
package versions in sync. Android versionCode is derived from the same version.

Windows preserves the existing app identity and data paths. Use the same install
folder and select Do not uninstall when upgrading. Save work and quit first.

Android uses package com.anf.workspace. Always reuse the original signing key
from the original release workspace. Back that key up
privately; do not publish it with the release or source repository. Losing the key
prevents compatible in-place updates. The release APK stays unsigned when the
original key is absent; the debug APK uses a test certificate. Export a
conversation backup before uninstalling or changing devices.

Before release: run Windows native and frontend regression checks, check the
Android frontend, verify APK signatures and package version, and test the UI with
sample data at phone and tablet widths. Physical Android device testing is still
required for full validation of the native file picker, read-aloud, and export.
Do not claim on-device Android AI, OCR, automatic browser replies, or cloud quota
bypasses. The first Android edition intentionally uses external browser accounts.

Build tools are installed only in this workspace. Android requires a full JDK 21,
Gradle 9.4.1 and Google Android SDK platform 37.0 with build-tools 36.0.0.
Target SDK remains 35. No global Java installation is required.
